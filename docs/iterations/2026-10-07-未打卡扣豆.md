# 2026-10-07 未打卡扣豆

第一次打卡之后，已经过去却整天没打卡的日子，会自动扣豆。用来对付「玩疯了、忘了打开」的情况。

## 哪天会扣

- 起点是这个孩子**第一次有打卡**的那天。这一天本身不扣。更早的空白日子也不扣。
- 从第二天起，到昨天为止，某一天一条打卡都没有，就扣一次。
- 今天还没过完，不提前扣。明天如果今天仍没打卡，才会扣今天。
- 同一天只结算一次。后来把数量改大，已经扣过的日子不会再补扣。

## 标签

放在扣豆标签最上面，深红色，名称固定为「未打卡扣豆」。

- 不能删除，也不能改名字和颜色。
- 只能改数量，单位是小豆。默认 **10**（1 颗大豆）。
- 改成 **0**：之后的漏打卡不扣。这段时间漏掉的日子记成「已跳过」，以后再把数量改回去，也不会回头扣这些天。
- 不出现在每天的打卡弹层里，不能手动点。

## 豆不够时

按当天要扣的数量和当时剩下的豆比：

- 够扣：只扣豆，不锁兑奖。
- 不够扣：能扣的扣到 0（不会扣成负数），并进入危险模式。豆条变红，不能兑奖。解锁方式与危险日相同：当天再新加超过 5 颗。

普通扣豆标签仍然可以扣成负数；这条不一样，走的是危险日那套「扣到 0 再冻结」。

## 月历和总结

- 被扣过的日子格子变成深红色，中间是扣掉的小豆数，底下写「未打卡」。盒子不再是「待开」。
- 月度总结的小豆合计会减去这些扣豆，行为次数里单独有一条「未打卡扣豆」。

## 数据

- `BehaviorTag.systemKey = missed_day`：这条内置标签。
- `MissedDaySettle`：每个档案、每个日期一行，记下扣了多少、是否因此冻结。用来保证不重复扣。
- 流水原因：`missed_checkin`。数量为 0 的跳过不写流水，只留下结算行。
